{% load static i18n %} {% get_current_language as LANGUAGE_CODE %} {% comment %} The operator's administrative shell. A standalone layout rather than ``{% extends "base.html" %}``, which is what the staff console used to do. The product chrome that must not appear here — the workspace switcher, the "+ New" menu and its idea modal, the connected-channels list, the organization footer — sits OUTSIDE ``{% block sidebar_nav %}`` in base.html, so overriding that block (the trick layouts/settings.html uses) only removes the middle of the sidebar and leaves the rest. An operator account owns no organization and no workspace by design (apps/accounts/management/commands/create_operator.py), so every one of those links pointed at a workspace it does not have. Deriving from base and wrapping each of those regions in a ``{% if not admin_area %}`` was the alternative. Rejected: it would make base.html carry the admin area's rules in five places, and the next product widget added to the sidebar would leak in here by default. Separate file, opt-in: a new product surface cannot appear in the administrative area by accident. Visual language is deliberately the product's (same stylesheet, same stone/orange tokens, same ``sidebar-nav-item`` class) so this does not read as a different application — only the navigation differs. The sidebar is a dark stone rail, which is the one cue that says "you are administering, not using". Nothing here is an access control: every view under this layout is decorated with ``_staff_required`` (apps/billing/views.py). The ``is_operator`` checks in the markup only decide what is drawn. {% endcomment %} {% block title %}{% translate "Administration" %} - Brightbean{% endblock %} {% block extra_head %}{% endblock %} {% csrf_token %}
