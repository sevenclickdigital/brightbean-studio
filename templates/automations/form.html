Three Alpine components, all of the same shape: they own a JS array, render it with x-for, and mirror it into a hidden input as JSON on every change. The hidden input is the field the form actually validates — the visible inputs carry no ``name`` at all, which is deliberate: a stray name would post a second, unvalidated copy of the same data. Serialisation happens on every mutation (``$watch`` on the array) rather than on submit. A submit handler is one event away from not running — the Enter key in a text input, a hx-post from the Test button — and a hidden input that is one edit stale is a rule that silently saves the previous keyword list. {% endcomment %}
